## 01｜Agent 开发岗位版：STAR 完整版

### Agent Skill 自动化评估与工具调用验证框架

**技术栈：** Python、Codex CLI、subprocess、JSON Schema、JSONL、SHA-256、unittest。

**S｜项目背景**

面向数据库性能报告和金融事实核查两类已有 Skill，Agent 的最终答复难以直接证明工具是否实际执行、证据是否有效以及用户要求是否完整满足，需要建立可复查的任务执行与评估链路。

**T｜项目目标**

构建本地 Agent 评估框架，将用户请求、Skill 执行、工具取证和结果判定连接起来，区分业务错误、证据不足与运行阻塞，并形成可重复执行的场景基线。

**A｜关键行动**

- 基于 Python 和 Codex CLI 开发独立会话执行器，按白名单注入任务、固定时钟和 Skill 快照，将公开输入与裁判真值分开，保存请求、JSONL 事件、工具回执、答复与 usage。
- 开发金融工具替身与 JSON Schema 输出约定，模拟结构化查询、资讯检索和依赖故障，核验实际调用、证据引用、数值口径及 0/1/2/null 真实性评分。
- 设计数据库、金融各 22 条用例，结合独立真值、六维 Rubrics、mandatory/fatal 规则和响应哈希绑定的 LLM 复核，验证任务完成度及异常停止行为。

**R｜实际结果**

形成 **44 条结构化用例**；完成主模型金融受控基线 **22/22 通过**及 LLM 复核，并保留两个金融场景各 3 次观察和第二模型 3 条抽样结果；定位数据库数据解析、用户范围遗漏和交付约束问题，形成证据与修复优先级。结果仅适用于当前已执行范围，未证明真实金融端到端成功或全面跨模型稳定。

**适配重点：** Agent 评估、工具调用、结构化输出、证据追溯、异常停止。更适合 Agent 工程与评估结合的岗位；若 JD 重点为 RAG、训练、多 Agent 或线上服务，应补充对应实作，本项目不提供这些经历证明。

### 针对 JD②：AI Workflow 执行与工具调用评估框架

**S｜背景：** 两类 Skill 涉及脚本执行、结构化查询和资讯取证，仅凭最终答案或工具返回状态，无法确认整条 AI 工作流是否正确完成任务。

**T｜目标：** 建立可配置、可追溯的执行与判定流程，明确工具参数、回执、输出结构和失败语义。

**A｜行动：** 使用 Python／Codex CLI 编排“任务输入—Skill 加载—工具取证—结构化输出—自动判定”，支持按套件、用例、模型和重复次数配置；封装子进程工具替身，记录参数、状态、证据标识与响应哈希；使用 JSON Schema 和独立 Judge 核验结构、事实与引用，并将自由文本送入单独复核。

**R｜结果：** 建立 44 条场景用例和 38 项裁判校准测试，完成主模型金融受控基线 22/22 通过及 LLM 复核，保留重复样本和第二模型抽样结果，形成可供回归对照的执行证据。

**面试定位：** 当前做的是可执行工具接口和评估工作流，具备进一步接入标准 Function Calling 的基础；项目尚未实现三家厂商的原生调用协议转换。

### 针对 JD③的使用方式

使用上面的“Agent Skill 自动化评估与工具调用验证框架”版本。自我介绍时先讲 Skill、工具取证和评估，再讲 Python 工程实现；不要把技能栏扩写成 LangChain、RAG 或向量数据库开发。若有其他真实后端、课程或科研项目，用它们补通信协议与服务开发能力。

## 02｜测试开发岗位版：STAR 完整版

### 面向 Agent Skill 的分层自动化测试与质量评估

**技术栈：** Python、argparse、subprocess、unittest、JSON 兼容 YAML、JSONL、SHA-256。

**S｜项目背景**

数据库报告和金融核查 Skill 的输出同时包含数据处理、工具调用和自然语言解释，存在“脚本退出成功但数据失真”“报告生成但遗漏核心要求”等风险，单靠文件存在或人工浏览难以可靠验收。

**T｜项目目标**

建立用例驱动的分层自动化评估工具，验证输入处理、业务正确性和交付完整性，准确区分被测缺陷与环境阻塞，并交付可复现的失败证据和回归条件。

**A｜关键行动**

- 从需求与风险拆解 44 条用例及覆盖矩阵，覆盖四类报告、五种数据入口、0/null 边界、中英文 AND/OR、金融阈值和故障配对；以同源 90 条记录构造 JSON/CSV/XLSX 等价输入。
- 使用 Python 开发组件、流水线、Agent 测试入口和独立真实依赖检查，保存命令、日志、产物与执行状态，区分 PASS、FAIL、BLOCKED、NOT_RUN 和待复核。
- 基于原始日志、记录集合和官方财报字段实现独立 oracle，核对逐行数据、单位、日期及引用；编写 38 项正反例校准测试，验证错值、错行、伪引用、缺项与泄露场景的判定。

**R｜实际结果**

**38 项裁判校准全部通过**；在 20 条数据库组件用例中检出 **9 条失败**，6 次流水线调用均识别出未满足完整验收的问题；定位 300 秒误读为 2026 秒、0/null 处理失真和 12 条专项范围遗漏，交付原始证据、定位依据及修复后的回归条件。失败用例数不等于独立缺陷数，当前未完成业务 Skill 修复后回归。

**适配重点：** 自动化框架、测试设计、独立 oracle、故障注入、质量门槛、缺陷定位。相比通用功能测试，重点体现对非确定性 Agent 输出和评估器本身的验证能力。

### 投 Agent 开发

**Agent Skill 自动化评估框架｜Python / Codex CLI / JSON Schema**

**项目描述：** 面向数据库报告与金融核查两类 Skill，构建可复跑的 Agent 执行与评估框架，验证工具取证、业务正确性和任务完成度。

- **执行编排：** 针对 Agent 任务难复现的问题，基于 Python／Codex CLI 开发独立会话执行器，固定任务输入、时钟与 Skill 快照，保存请求、事件和答复，形成逐用例可追溯的执行记录。
- **工具取证：** 针对工具调用与答案依据难核对的问题，封装金融工具替身，模拟结构化查询、资讯检索及依赖失败，关联实际回执与证据引用，支持异常停止和口径校验。
- **任务评估：** 针对输出结构完整但任务可能未完成的问题，设计 44 条用例，结合 JSON Schema、独立真值、六维 Rubrics 和必需项门槛，检查数值、范围、引用及交付要求。
- **语义复核：** 针对自动规则难判断自由文本的问题，建立响应 SHA-256 绑定的 LLM 复核流程，完成 32 份当前条件输出的复核，保留证据说明及原自动失败，支持结果追溯。
- **基线验证：** 在固定输入与工具快照下，完成主模型金融受控基线 22/22 通过及 LLM 复核；对两个场景分别形成 3 次观察，并完成第二模型 3 条抽样，保留基线与额外样本供回归对照。

### 投测试开发

**Agent Skill 分层测试与评估工具｜Python / unittest / subprocess**

**项目描述：** 面向数据库报告与金融核查两类 Skill，开发分层自动化测试与独立判定工具，识别脚本成功背后的数据错误、需求遗漏和交付缺项。

- **用例设计：** 围绕输入处理、业务规则与交付风险，设计 44 条用例及覆盖矩阵，覆盖 0/null、AND/OR、金融阈值和故障配对；以同源 90 条记录构造 JSON/CSV/XLSX 等价输入，支持接入一致性验证。
- **分层执行：** 为区分组件缺陷、流程问题与运行阻塞，使用 Python 开发组件、流水线和 Agent 执行入口，另设真实依赖检查，保存命令、日志和产物，分别记录通过、失败、阻塞及待复核状态。
- **独立断言：** 针对中间结果可能复制上游错误的问题，基于原始日志、记录集合和官方财报字段建立独立 oracle，逐项核对记录身份、数值、范围和引用，识别多格式一致但原始数据错误的情况。
- **裁判校准：** 针对自动评估可能误判的问题，编写错值、错行、伪引用、必需项缺失和测试密钥泄露等 38 项正反例校准测试，全部通过，验证 Judge 对已知错误的判别能力。
- **缺陷定位：** 在 20 条数据库组件用例中检出 9 条失败，6 次流水线调用均未满足完整验收；定位 300 秒误读为 2026 秒、0/null 失真和专项范围遗漏，交付原始证据、定位依据及回归条件。

| 255 项 | 结构与冻结哈希自检通过 | 本地自检；不是业务通过率或官方验收 |

| 0/6 | 6 次数据库流水线均未满足完整验收 | 脚本真实执行并产生产物；失败不等于运行器坏了 |

| 32 份 | 完成 32 份当前条件输出的 LLM 语义复核 | 22 基线 + 4 额外重复 + 3 数据库停止 + 3 第二模型抽样 |
