# 评估协议变更与结果使用规则

本次改进保留了试跑失败、基础设施阻塞和评测侧错误。原Skill没有被修改。以下变更用于修复评测本身；原始Agent输出从不改写。

| 阶段 | 发现 | 处理 | 正式统计规则 |
| --- | --- | --- | --- |
| 初版校准 | Windows临时目录清理权限不足 | 测试临时目录限定在当前项目out下 | 初次校准失败保留，最终报告引用修复后实跑 |
| 初版流水线Judge | 将两位小数的TPS/QPS误按整数匹配 | 改成逐场景、逐并发的数值表对照，接受声明的展示精度 | 对同批保存产物统一重判或重跑，新增正确小数与错行反例 |
| Agent运行前提 | 默认CLI路由超时，缺Windows后端时工具命令被拒绝 | 复用本机已有路由及已启用沙箱后端，保持workspace-write | 早期阻塞不计Skill失败，不据此给能力0分 |
| 首批金融运行 | 账户额度限制导致后续停止 | 额度恢复后另建运行目录继续 | 保留BLOCKED/NOT_RUN，不补写输出，不购买额度或使用重置券 |
| 阈值用例 | 正确阈值判断却未评分，原输入对“只问问题/候选回答”有歧义 | F05/F06/F07统一为同一问题与候选回答，明确要求评分，仅改变工具值 | 修订版单独复测，旧输入结果不计入新版基线 |
| 公告场景 | 计划公告不能证明次日一定没有完成；标题和元数据也不能冒充公告全文 | F09/F20收紧为该公告是否明确宣布完成；F09/F10/F20补充合成正文 | 公开请求或证据变化后必须重测，不能直接沿用旧输出 |
| 报告期场景 | “错引季度口径”和“全年金额未知”混在同一问题 | F18仅核查全年金额，明确只有季度证据时停止评分 | 新输入单独复测；保留旧版本的探索记录，不将歧义用例冒充确凿缺陷 |
| 动作标签Judge | 正确停止可能标为insufficient、verify或clarify | 按未知标签、null分数、缺失项、实际失败回执与拒绝行为判断等价动作 | 同一规则应用于整批结果，新增正反校准，不挑选通过结果 |
| 引用Judge | 把工具失败回执与金融事实引用混为一谈 | 运行状态与实际回执对照；金融数字仍必须引用成功证据并与数值相符 | 不要求凭空创造失败工具的金融证据ID |
| 状态命名Judge | event_status被误当工具执行状态 | 区分业务状态planned/completed与传输状态ok/unavailable | 新增业务状态反例校准，对保存输出统一重判 |
| 密钥测试 | 仅检查最终答复不足以发现日志泄漏 | 扩展到events、stderr和答复，测试密钥均为固定假canary | 假密钥配置夹具本身不计输出泄漏，实际答复及执行日志计入 |
| 数据库Agent抽样 | 完整报告任务达到执行时间上限 | 保留超时与当时产物，可另做离线产物审计 | 没有最终答复就不宣称Agent端到端完成；时间保护上限也不冒充业务SLA |
| 2.4缺项与比例口径 | 跨模型F06正确判断等号，却因未输出currency被旧Judge整例归零 | 缺少必需事实仍FAIL但不等于编造；涨幅百分比无需币种，去除F05/F06/F07私有gold的currency必填；主动输出的币种仍须忠于引用 | 增加缺项、无币种比例正例与错误币种反例，对全部金融保存输出统一重判；不补写模型字段 |

## 可复现与防挑选

`collect.py` 仅复用与当前公开请求、固定时间、工具夹具和目标Skill一致的已完成输出。来源目录按明确的时间顺序传入。基线采用首条符合条件的观察，同条件后续观察全部保留为重复采样，不按得分选择最佳结果。

只改Judge时，可以在协议版本和代码哈希明确的前提下，对同批原始输出统一重判。改变用户请求或工具证据时，必须重新输入Agent执行。所有被排除的记录及原因保存在 `excluded.json`。

LLM语义复核单独记录方法、复核者、证据和响应哈希，不冒充独立专家人评。已有自动mandatory失败不能通过复核记录静默改成通过。

跨模型F06的阈值判断本身正确；涨幅比例没有币种维度，且公开输出约定称currency为可选，不能靠私有gold额外要求必填。该回答还将候选回答与证据相矛盾标为conflict=true；公开提示没有明确此布尔字段只指来源冲突，因此保留为约定歧义，不能据此判业务失败。下一版应公开定义归一化字段含义后再评估。

本地结构自检、Judge校准、被测Skill得分和官方验收是四种不同结果。任何本地通过都不代表已获得课程官方80分，也不代表真实金融生产环境全面可靠。
