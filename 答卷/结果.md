# 实测结果与改进建议

本答卷已补齐“意图 → 验收 → 场景 → 样例与真值 → Agent执行 → 判定 → 复核 → 回归建议”的证据链。数据库与金融各22条用例，协议2.4。原提交及原Skill保持不变；本次完善的是评估设计、执行工具和证据，不是把被测业务代码改到通过。

可以证明原答卷存在错误真值、错误放行和执行证据不足；没有评委反馈，仍不能确认这些就是当时落选的实际原因。原材料逐项复盘见[复盘](复盘.md)。

## 3 数据库发现及修复优先级

**先修数据失真。** D01原始日志明确写Duration: 300s、产品TDSQL-B-v22.7.2；原组件得到2026秒和sysbench。错误在接入时产生，后续三格式一致复制也不能算正确。D16把真实零值当缺失处理，导致记录丢失；D17数组中的null QPS被补写，质量门控未按要求停止。建议修复字段解析和缺失判断，再对原日志、零值、null以及普通正例同时回归。

**再修用户任务范围。** D04要求3产品×2场景×2并发，共12条，比较QPS/P95/P99并提出选择依据。原分析按全量数据分桶，只给平均QPS/P95，缺P99和有依据的选型。建议在分析前固定筛选集合并保存记录身份，再用同一集合生成表格、图表和结论。D21/D22还暴露标准英文字段AND/OR条件未被正确解析，中文成功不能代替英文覆盖。

**补齐接入和交付约束。** D07/D08标准粘贴对象入口不能正常消费；D14只有两个版本却产生趋势结构。所有6次流水线均缺强制block_map和analysis_proposal；横向对比只有17张图，低于reference要求的20张；专项只有2张，低于3张。建议在生成流程加入明确的交付检查，不能以“文件存在、程序退出0”替代任务验收。

**区分组件缺陷和Agent补救。** D07的Agent读取规范后直接对完整records调用quality_check，正确发现QPS空值并停止；这不能反推原适配器没有问题。D01的Agent确实把产物元数据修正为300秒和正确产品，但360秒内没有最终答复，故保留BLOCKED。下一步应在固定相同输入下单独验证完整报告交付、L1/L2/L3洞见、排版和响应时间；当前没有这些通过证据。

## 4 金融结果的适用范围

受控基线覆盖0/1/2/null、仅问题入口、2.99/3.00/3.01阈值、旧日期、计划/完成、依赖失败、拒绝内部链接、假密钥、ADR市场、报告币种、季度/全年、来源冲突、资料注入、技术周期及资金流日期。这批输出能完成对应核查，并说明证据不足。

原工具真实返回另有重要问题：2024-12-31年度记录包含OperatingIncome约7129.897亿元、CurrencyType为港币/港元；资讯检索返回营收6602.57亿元、同比8.41%。官方年报真值为人民币6602.57亿元，业绩公告同比约8%。接口换算口径、报告币种和原报表字段必须进一步核对；不能把接口成功视为独立事实成立，也不能未经分析就把所有差异归因于模型编造。详见[live3原始返回](out/live3/westock.stdout.txt)与[资讯返回](out/live3/search.stdout.txt)。

受限环境中的第二次资讯探测曾40秒超时，见[live2](out/live2/results.json)；获准联网环境下随后返回。该差异不能直接归因为服务不稳定。两次记录均保留。

跨模型F06曾被旧Judge判失败，因为缺currency字段。百分比无币种维度，公开提示也未要求必填，因此2.4去除此过度约束，同时保留主动输出错误币种时的失败检查。缺少其他必需事实仍失败，但不当作编造整例归零。全批原输出统一重判后的结果见正式报告；旧失败仍在[out/cross](out/cross/report.md)。这证明评估器也需要被测试，不能为了“找到缺陷”而误杀正确回答。

## 6 下一步与能力补全

1. 先按学习.md完成独立真值、控制变量和Judge反例练习；能用一条轨迹解释“预期、实际、差异、原因、修复验收”。
2. 在新的Skill副本上修复数据库数据失真与门控问题，保持本套真值和Judge冻结，产出修复前后差异；原Skill快照继续保留。
3. 为数据库四种报告补完整Agent交付测试；给L1/L2/L3、图表可读性及三格式排版增加独立专家复核。当前流水线失败已足以阻止准入，不能用金融100分抵消。
4. 给金融增加真实Agent取证、复杂多来源冲突、资料更正、技术指标和资金流的配对正例。将conflict等归一化字段含义写入公开输出合同后，再评字段语义。
5. 将重复与跨模型从当前小样本扩展到预先选定的关键场景，设定业务响应时限和成本预算。当前超时是运行保护参数，尚不是业务SLA。

尚未完成的范围：官方完整Meta-Testcase、严格物理隔离/双盲、独立专家人评、数据库完整Agent成功交付、真实金融Agent端到端、多轮会话、广泛跨模型稳定性，以及业务Skill修复后回归。运行器对超时主要终止直接子进程，未验证所有后代进程都能清理；长跑或CI部署前需补进程树治理。

## 7 项目技术栈与简历边界

本次新增评估实现使用Python 3.12、argparse/subprocess/unittest/pathlib/hashlib、JSON兼容YAML 1.2、JSON Schema、JSONL轨迹、Codex CLI及PowerShell。评估技术包括独立oracle、Rubrics加权评分、mandatory/fatal门槛、工具替身、控制变量、故障注入、变异校准、哈希冻结、语义复核和重复抽样。

原数据库Skill使用NumPy、Matplotlib、python-docx、openpyxl，生成Markdown/HTML/DOCX；这些业务实现属于课程提供代码。金融真实依赖使用westock Node CLI与mx-finance-search Python工具，本项目调用并评估它们，没有自行实现行情服务。

独立复跑并能解释后，可写：“围绕数据库性能报告与金融核查两类Skill，建立44条结构化用例，开发Python分层评估与证据留存工具；通过独立真值、受控工具与Judge反例定位数据失真、范围遗漏和评测误杀，完成主模型22条金融受控用例执行及抽样复核。”

不要写成开发了两套完整业务Skill、建立生产金融系统、获得官方满分，或已证明跨模型全面稳定；当前没有这些事实。
